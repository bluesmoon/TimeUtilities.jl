TimeUtilities — Module
TimeUtilities

A Julia module providing utilities for working with dates, times, and timezones to fill some convenience gaps left in the standard Dates and TimeZones modules.

In particular, it

  • adds a Base.trunc method to truncate a DateTime to the start of the week, which is the only deterministic variant missing in Dates.jl
  • adds ZonedDateTime constructors for FixedTimeZone that accept and discard a DST ambiguity parameter. The constructors in TimeZones.jl do not accept the DST ambiguity parameter for FixedTimeZones thus making it hard to implement generic code that does not require slow exception handling.

This module also includes

  • code to parse dates and times with and without timezones from strings using a series of common formats, iterating through the list till it finds a match,
  • Convenience functions to convert to and from epoch milliseconds,
  • A NormalizedTimeType container struct that can hold multiple representations of a time value,
  • Types for representing time windows, which are tuples of two TimeTypes or two NormalizedTimeTypes,
  • and a function to convert LEGACY timezone abbreviations to the most likely matching standard timezone name, with a fallback to UTC for unrecognized abbreviations.

TimeUtilities.NormalizedTimeType — Type

A container type for various views of a given TimeType which, via converters, may be used as a TimeType itself.

  • struct NormalizedTimeType

Fields

tz::TimeZone : The TimeZone of the contained TimeType. timezone is an alias of this field to make it a drop-in replacement for ZonedDateTime.

timeUTC::DateTime : The UTC converted representation of the contained TimeType. utc_datetime is an alias of this field to make it a drop-in replacement for ZonedDateTime.

timeTZ::ZonedDateTime : A ZonedDateTime representing the contained TimeType and its TimeZone

timeMS::Int64 : The contained TimeType represented as milliseconds since the Unix Epoch of 1970-01-01T00:00:00.000Z

Constructors

NormalizedTimeType(::TimeType) : Constructs a NormalizedTimeType from a TimeType. The passed in TimeType may be a Date, a DateTime, a ZonedDateTime, or any other subtype of TimeType

NormalizedTimeType(::TimeType, ::TimeZone|AbstractString) : Constructs a NormalizedTimeType from a DateTime with an associated TimeZone. The second parameter may either be a TimeZone object or a string TimeZone name.

Converters

NormalizedTimeType has converters for DateTime, ZonedDateTime, and Int64, so it may be used wherever one of these three types is required.

Operators

You may also add and subtract any Dates.Period or Dates.CompoundPeriod to/from a NormalizedTimeType object to get a new NormalizedTimeType object.

For example:

julia> t1 = NormalizedTimeType(Date(2016, 10, 10))
TimeUtilities.NormalizedTimeType(UTC,2016-10-10T00:00:00,2016-10-10T00:00:00+00:00,1476057600000)

julia> t1 + Dates.Month(1) - Dates.Day(2)
TimeUtilities.NormalizedTimeType(UTC,2016-11-08T00:00:00,2016-11-08T00:00:00+00:00,1478563200000)

julia> t1 - Dates.Month(1) + Dates.Week(1)
TimeUtilities.NormalizedTimeType(UTC,2016-09-17T00:00:00,2016-09-17T00:00:00+00:00,1474070400000)

Examples

julia> NormalizedTimeType(Date(2016, 10, 10))

Internal Methods and Constants

TimeUtilities.DATE_FORMATS — Constant

Ordered list of (Regex, DateFormat) pairs for parsing timezone-naïve date/time strings.

Each entry matches a specific string pattern and provides the corresponding Dates.DateFormat to parse it into a DateTime. Patterns are tried in order; the first match wins.

Supported formats:

  • yyyy-mm-dd HH:MM:SS[.sss] — space separator, optional milliseconds
  • yyyy-mm-ddTHH:MM:SS[.sss] — ISO 8601 T separator, optional milliseconds
  • yyyy-mm-ddTHH:MM:SS[.sss]+ — trailing + sentinel (offset stripped by caller)
  • yyyy-mm-ddTHH:MM:SS[.sss]- — trailing - sentinel (offset stripped by caller)

Used by timestampToZonedDateTime for strings without a numeric timezone offset. For timezone-aware strings see DATE_FORMATS_TZ.

TimeUtilities.DATE_FORMATS_TZ — Constant

Ordered list of (Regex, DateFormat) pairs for parsing date/time strings that embed a numeric timezone offset.

Each entry matches a specific timezone-aware pattern and provides the corresponding Dates.DateFormat to parse it into a ZonedDateTime. Patterns are tried in order; the first match wins.

Supported offset formats (combined with both T-separator and space-separator date-time):

  • ±HHMM — compact offset, e.g. +0400
  • ±HH:MM — colon-separated offset, e.g. -05:30
  • HHMM — space-separated offset, e.g. 0400

Milliseconds are optional in all patterns.

Used by timestampToZonedDateTime for timezone-aware strings. For timezone-naïve strings see DATE_FORMATS.

TimeUtilities.common_tz_abbrs — Constant

Internal dictionary of common legacy timezone abbreviations to their full TimeZone names.

We use this dictionary because timezonesfromabbr returns multiple results that all match the offset of the common abbreviation. Rather than pick a random one, we use the most likely candidate based on colloquial usage. For example, "EST" is used in multiple timezones, but the most common usage is "America/New_York". This dictionary is used to disambiguate these cases.

Used by expand_legacy_timezone.

TimeUtilities.normalizeTimestamps — Method

Normalize multiple TimeTypes to NormalizedTimeTypes

  • normalizeTimestamps(t...) → NormalizedTimeType[...]
  • normalizeTimestamps(tz, t...) → NormalizedTimeType[...]

TimeType is the common supertype for DateTime, Date, ZonedDateTime and others.

Arguments

tz::AbstractString|TimeZone : [optional] The common timezone to use for all ts that don't have their own TimeZone

t::TimeType... : The time values to normalize.

Returns

An array of NormalizedTimeType

Example

julia> norms = TimeUtilities.normalizeTimestamps(

TimeUtilities.timestampToZonedDateTime — Method
  • timestampToZonedDateTime(::DateTime, ::TimeZone) → ZonedDateTime
  • timestampToZonedDateTime(::Date, ::TimeZone) → ZonedDateTime
  • timestampToZonedDateTime(::AbstractString, ::TimeZone) → ZonedDateTime
  • timestampToZonedDateTime.(::Vector, ::TimeZone) → Vector{ZonedDateTime}

Convert a compatible object to a ZonedDateTime with a specified TimeZone.

Any incompatible objects are returned as-is, which makes this suitable to call on Vectors of mixed types (such as missing).

If called on a String, will check DATE_FORMATS and DATE_FORMATS_TZ for a suitable parser.

If the object represents a timestamp that isn't valid in the specified timezone, then this function will attempt to determine the most appropriate value by checking the delta with the DST transition, applying that to the UTC equivalent, and then converting.

Use the broadcast operator to apply this to a Vector.
